Before this goes live

What to set up, and what must stay secret

Short version: you do not need to make anything secret for this to work. Two public links go in one file, and that is it. This page explains which is which, so you never accidentally paste a real credential into the website.

The rule in one line

Anything you paste into the website is public. Real secrets belong on Google's side, not in this repo. There are no real secrets in this setup — just two links that are safe to share.

What you need, in order

Three things, about twenty minutes total. You only do this once.

Step one

The Apps Script web app

This is the bridge between the website and your Google Sheet. It is what receives an entry and writes a row.

  1. Open your Sheet The one you already use for the Luxia league.
  2. Extensions → Apps Script A code editor opens in a new tab.
  3. Paste the server code below Replace anything already in Code.gs.
  4. Deploy → New deployment Type: Web app. Execute as: Me. Who has access: Anyone.
  5. Copy the /exec URL It ends in /exec. That is the value for scriptUrl.

"Anyone" is required and is the part that worries people. It means anyone can call the script, not that anyone can read your Sheet. The script decides what it will accept, and it only ever appends a booking row. It cannot read your data back out.

The server code

Paste this into Apps Script. It creates the entries tab automatically if it does not exist. 

// Pringle Padel — booking intake
// Runs inside Google's servers. This is where anything genuinely
// sensitive would live (Script Properties), never in the website.

const SHEET_NAME = 'Entries';
const HEADERS = ['Reference','Event','Name','Partner','Rank',
                 'Mobile','Email','Notes','Paid','Entered','PaidAt'];

function doPost(e) {
  const lock = LockService.getScriptLock();
  try {
    lock.waitLock(20000);            // serialise concurrent submissions
    const b = JSON.parse(e.postData.contents);

    // Minimal validation — never trust a public endpoint.
    if (!b.ref || !b.name || !b.eventId) {
      return json({ success: false, message: 'Missing required fields.' });
    }

    const ss = SpreadsheetApp.getActiveSpreadsheet();
    let sh = ss.getSheetByName(SHEET_NAME);
    if (!sh) {
      sh = ss.insertSheet(SHEET_NAME);
      sh.appendRow(HEADERS);
    }

    // Reject a duplicate reference rather than writing a second row.
    const refs = sh.getRange('A2:A').getValues().flat();
    if (refs.indexOf(b.ref) !== -1) {
      return json({ success: true, message: 'Already recorded.' });
    }

    sh.appendRow([
      b.ref, b.eventId, b.name, b.partner || '', b.rank || '',
      b.mobile || '', b.email || '', b.notes || '',
      'NO',                                  // Paid — Lea flips this
      new Date(),
      ''
    ]);

    return json({ success: true, ref: b.ref });

  } catch (err) {
    return json({ success: false, message: String(err) });
  } finally {
    lock.releaseLock();
  }
}

// The organiser page calls this to flip someone to paid.
function doGet(e) {
  const action = e.parameter.action;

  if (action === 'markPaid') {
    // NOTE: in this simple version the passcode travels in the URL.
    // See "Making it properly secure" below to move it here instead.
    const sh = SpreadsheetApp.getActiveSpreadsheet()
                 .getSheetByName(SHEET_NAME);
    const ref = e.parameter.ref;
    const paid = e.parameter.paid === 'true';

    const refs = sh.getRange('A2:A').getValues().flat();
    const row = refs.indexOf(ref) + 2;
    if (row < 2) return json({ success: false, message: 'Unknown reference.' });

    sh.getRange(row, 9).setValue(paid ? 'YES' : 'NO');   // column I
    sh.getRange(row, 11).setValue(paid ? new Date() : ''); // column K
    return json({ success: true, ref: ref, paid: paid });
  }

  // Default: hand back the current entry list.
  const sh = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(SHEET_NAME);
  if (!sh) return json({ success: true, rows: [] });
  const values = sh.getDataRange().getValues();
  const head = values.shift();
  return json({
    success: true,
    rows: values.map(r => {
      const o = {};
      head.forEach((h, i) => o[h] = r[i]);
      return o;
    })
  });
}

function json(obj) {
  return ContentService
    .createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}

After pasting, click Deploy → Manage deployments and re-deploy whenever you change this code, or the live URL keeps running the old version. That catches everyone out at least once.

Step two

The published Sheet link

So every visitor sees the same confirmed entry list, not just their own entries sitting in their own browser.

  1. Open the SheetFile → Share → Publish to web.
  2. Pick the entries tabFormat: Comma-separated values (.csv).
  3. Publish, then copy the linkThat is the value for sheetCsvUrl.

Publishing exposes the whole tab. It becomes readable by anyone with the link. That is fine for names and events, which are already shown publicly. Do not publish a tab containing player phone numbers or emails. Keep contact details in a separate tab, or leave them in the entries tab but publish only the columns you need.

Step three

The organiser passcode — and being honest about it

You asked what needs to be secret. The honest answer: on a static website, nothing can be truly secret. Any passcode you put in the page can be found by someone who looks.

So treat it as what it is — a lock on a door, not a vault. It keeps the page out of casual view and out of search results. That is genuinely useful, and it is enough for this use case, because the worst thing a stranger can do is tick someone as paid. No money moves. You can undo it.

Making it properly secure (only if you ever need it)

If you later want real protection, the pattern is: keep the passcode on Google's side and have the site send it up for checking. The site then never contains the value at all. 

// 1. In Apps Script: Project Settings → Script Properties
//    Add a property named ADMIN_KEY with a long random value.
//    This lives on Google's servers and is never in the website.

// 2. In doGet, check it before doing anything:
const ADMIN_KEY = PropertiesService.getScriptProperties()
                    .getProperty('ADMIN_KEY');

if (e.parameter.action === 'markPaid') {
  if (e.parameter.key !== ADMIN_KEY) {
    return json({ success: false, message: 'Not authorised.' });
  }
  // ... then flip the paid flag
}

Lea then types the passcode into a box on the organiser page, and it is sent with each action rather than being stored in the page. Still not perfect over a shared link, but a real step up, and the value never ships in the repo.

Summary

Direct answer to your question

Add your own Google link

Yes. Both links are yours to create and both are safe to put in config.js. Nothing needs to be hidden for this to work, and nothing needs to be bought.

What to keep secret

Your Google account password, any API keys, and your bank login. None of those go in this repo, ever. If you are ever unsure whether something is safe to paste here, it is not.
